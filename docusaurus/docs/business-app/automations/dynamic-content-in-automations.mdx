Dynamic content refers to placeholders you add to message content, such as email body or SMS text, that are replaced with real data when the automation runs. For example, you can insert the contact's name, a task ID from the trigger, or a form response. That way your messages stay personalized and accurate without typing each value manually.

## How to use it

You can use dynamic content in any step that sends or displays text, such as `Send an SMS message via Conversations`, `Send a plain text email via Conversations`, and other messaging steps in the Automation Builder.
When you're editing the message content (for example, the `SMS content` field, or an email's body or subject line), click the `Insert dynamic content` button <img src={require('./img/dynamic-content-insert-button.png').default} alt="Insert dynamic content button" style={{height: '1.4em', verticalAlign: 'middle'}} /> to browse available values, pick one, or type the syntax directly.

<img src={require('./img/automations-dynamic-content-sms-body.png').default} alt="SMS content field with a message that uses the dynamic content {.WorkflowStep.trigger.list_id} and {.WorkflowStep.trigger.company_id}, a 160 / 1000 character counter, and the Insert dynamic content button" width="50%" />

### What type of content can you add?

Click `Insert dynamic content` to open the `Add dynamic content` dialog. Under "What type of content do you want to add?", choose a `Category`:

- `Automation details`: Details about the automation run, such as the date and time the automation ran.
- `From a previous step`: Information from the trigger (the event that started the automation) or from an earlier step. Choose the step, such as `Trigger`, and then the field you want.

For example, if the trigger is "When a company is added to a list," you can insert the company ID or the list ID into your message. Click `Add` to insert the value, or `Cancel` to close the dialog without adding anything.

## How the syntax works

Dynamic content uses dot notation to locate the right piece of information. Every value follows the format `{.WorkflowStep.<step ID>.<field>}`. Think of it like an address with three parts:

| Part | What it means | Example |
|------|---------------|---------|
| **Workflow step** | The value comes from a step in this automation | `.WorkflowStep` |
| **Step ID** | Which step? The trigger is `trigger`. Other steps use an ID. | `.trigger` |
| **Field** | Which specific detail from that step? | `.task_id` |

**Example:** `{.WorkflowStep.trigger.task_id}`

- `.WorkflowStep`: Look at the workflow step.
- `.trigger`: Look at the trigger, the event that started the automation.
- `.task_id`: Grab the task ID from that event.

When the automation runs, this placeholder is replaced with the actual task ID (for example, "TSK-4821") in the email or SMS.

You can type dynamic content directly into the message field or use the `Insert dynamic content` button in the step to browse and insert available values for your workflow.

When you pull a value from an earlier step rather than the trigger, the step is identified by an ID instead of its name, for example `{.WorkflowStep.773dcc25-db4c-4d5d-882d-d3c8482e9770.response}`. To see which step an ID refers to, turn on [step references](./navigating-the-canvas.mdx#step-references) in the Automation Builder.

:::note
The automation must be turned on for dynamic content to be filled when the message is sent. If a value isn't available (for example, the trigger didn't provide it), the placeholder may be blank or show a fallback depending on the field.
:::
